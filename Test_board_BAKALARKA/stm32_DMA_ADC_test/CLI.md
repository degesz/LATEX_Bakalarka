# CLI Reference

This document describes the serial command interface exposed by the STM32 LCR meter firmware.

The CLI is implemented with `SimpleCLI` in `src/command_interface.cpp`.

## Serial Settings

- baud rate: `115200`
- line ending: `LF` or `CRLF`

Commands are line-based. Send one command per line.
After each command response, the firmware emits one extra blank line to make responses easier to separate in a serial terminal.

Example:

```text
status
capture 256 200000 voltage
dds 10000 1
```

## Startup Messages

On successful startup the firmware prints:

```text
ready,stm32f103_lcr_meter
```

If acquisition initialization fails, an error line is printed before the ready banner:

```text
error,<reason>
ready,stm32f103_lcr_meter
```

## Command Details

### `help`

Prints the command list generated by `SimpleCLI`.

Example:

```text
help
```

### `id`

Prints the device identifier and burst buffer capacity.

Example:

```text
id
```

Typical output:

```text
device,stm32f103_lcr_meter
firmware,acquisition_control
max_burst_samples,2048
```

### `status`

Prints the current acquisition settings, output settings, and latest lowpass/DC readings.

Example:

```text
status
```

Typical output:

```text
sample_rate_hz,200000
sample_count,256
dds_frequency_hz,1000
dds_enabled,1
amp_wiper,128
offset_pwm,0
shunt_range,0
voltage_pga,0
current_pga,0
v_lowpass_raw,2046
i_lowpass_raw,2051
```

### `adc [avg]`

Reads the slow lowpass/DC channels and prints raw ADC codes plus voltages.

Arguments:

- `avg`: number of averaging reads, default `16`

Example:

```text
adc 32
```

Typical output:

```text
v_lowpass_raw,2044
i_lowpass_raw,2050
v_lowpass_volts,1.647619
i_lowpass_volts,1.652454
```

### `capture [count] [rate] [channel]`

Captures a synchronous AC burst and streams one selected channel in CSV format compatible with the PC oscilloscope script.

Arguments:

- `count`: number of synchronous voltage/current sample pairs
- `rate`: requested sample rate in Hz
- `channel`: `voltage`, `current`, `v`, or `i`

Defaults:

- `count = 256`
- `rate = 200000`
- `channel = voltage`

Example:

```text
capture 512 250000 voltage
```

Output format:

```text
sample_rate_hz,250000
index,value
0,2038
1,2060
2,2075
...
```

Notes:

- The actual sample rate reported back is the configured timer rate after integer divider rounding.
- Requested sample rates must be between `1000 Hz` and `1000000 Hz`.
- On the current STM32F103 setup, `TIM3` runs from a `72 MHz` timer clock, so the reported rate is the nearest achievable divider result in that range.
- Valid sample count is limited by the burst buffer size.

### `capturepair [count] [rate]`

Captures a synchronous AC burst and prints both channels together.

Arguments:

- `count`: number of sample pairs
- `rate`: requested sample rate in Hz

Defaults:

- `count = 256`
- `rate = 200000`

Example:

```text
capturepair 128 100000
```

Typical output:

```text
sample_rate_hz,100000
dc_voltage_lowpass_raw,2047
dc_current_lowpass_raw,2052
index,v_raw,i_raw
0,2042,2037
1,2068,2059
2,2081,2074
...
```

This command is useful when host software needs both synchronous AC channels at once.

Sample-rate limits are the same as `capture`: request `1000..1000000 Hz`, then use the returned `sample_rate_hz` field as the actual configured rate.

### `measure [count] [rate]`

Captures a synchronous burst, converts both channels to physical units, runs a single-frequency DFT at the active DDS frequency, and reports amplitude, phase, and impedance.

Arguments:

- `count`: number of sample pairs
- `rate`: requested sample rate in Hz

Defaults:

- `count = 256`
- `rate = 200000`

Example:

```text
measure 512 200000
```

Typical output:

```text
sample_rate_hz,200000
dds_frequency_hz,10000
shunt_range,1
voltage_pga,0
current_pga,0
shunt_resistance_ohm,1000.000000
samples_per_period,20.000000
captured_cycles,25.600000
voltage_amplitude_v,0.120000
voltage_phase_deg,3.400000
current_amplitude_a,0.000118
current_phase_deg,-1.100000
phase_diff_deg,4.500000
raw_impedance_mag_ohm,1016.949158
raw_impedance_real_ohm,1013.815613
raw_impedance_imag_ohm,79.796631
calibration_status,missing_open
impedance_mag_ohm,1016.949158
impedance_real_ohm,1013.815613
impedance_imag_ohm,79.796631
```

Notes:

- ADC samples are converted from `0..3.3 V` and centered by subtracting `1.65 V`.
- Current is derived from the centered current-channel voltage and the active shunt value.
- The reported phase difference includes a fixed `180 deg` compensation for the inverted current analog path.
- Shunt mapping is `0=100 ohm`, `1=1 kohm`, `2=10 kohm`, `3=100 kohm`.
- Voltage and current PGA scaling currently use placeholder gain tables set to `1.0`; update `src/impedance_analyzer.cpp` with real analog gains later.
- `impedance_*` equals the raw result until both open and short calibration records are available for the active range/PGA/frequency combination.

### `cal [kind] [count] [rate]`

Stores a calibration record for the current frontend settings and DDS frequency.

Arguments:

- `kind`: `open` or `short`
- `count`: number of sample pairs
- `rate`: requested sample rate in Hz

Example:

```text
cal open 512 200000
cal short 512 200000
```

Typical success response:

```text
calibration_kind,open
sample_rate_hz,200000
dds_frequency_hz,10000
shunt_range,1
voltage_pga,0
current_pga,0
stored_impedance_real_ohm,14523.221680
stored_impedance_imag_ohm,-320.117035
ok,cal
```

Notes:

- Calibration is stored only in RAM and is lost on reset.
- Records are keyed by `shunt_range`, `voltage_pga`, `current_pga`, and exact `dds_frequency_hz`.
- The current implementation applies a two-term open/short correction to the measured complex impedance.

### `dds [freq_hz] [enable]`

Sets DDS frequency and output enable state.

Arguments:

- `freq_hz`: desired DDS output frequency in Hz
- `enable`: `1` to run, `0` to hold reset

Defaults:

- `freq_hz = 1000`
- `enable = 1`

Example:

```text
dds 10000 1
```

Success response:

```text
ok,dds
```

### `amp [value]`

Sets the MCP4561 volatile wiper value.

Full-scale reference: `amp 255` corresponds to approximately `3.55 Vpp`.

Arguments:

- `value`: `0..255`

Example:

```text
amp 180
```

Success response:

```text
ok,amp
```

Failure response:

```text
error,mcp4561 write failed
```

### `offset [value]`

Sets the PWM duty applied to `PA7` for generated source offset control.

Full-scale reference: `offset 255` corresponds to approximately `3.3 V`.

Arguments:

- `value`: `0..255`

Example:

```text
offset 140
```

Success response:

```text
ok,offset
```

### `range [value]`

Sets the 2-bit shunt range selector.

Arguments:

- `value`: `0..3`

Example:

```text
range 2
```

Success response:

```text
ok,range
```

### `vpga [value]`

Sets the 2-bit voltage PGA selector.

Arguments:

- `value`: `0..3`

Example:

```text
vpga 1
```

Success response:

```text
ok,vpga
```

### `ipga [value]`

Sets the 2-bit current PGA selector.

Arguments:

- `value`: `0..3`

Example:

```text
ipga 3
```

Success response:

```text
ok,ipga
```

### `led [r] [g] [b] [index]`

Sets one NeoPixel or all NeoPixels.

Arguments:

- `r`: red `0..255`
- `g`: green `0..255`
- `b`: blue `0..255`
- `index`: pixel index, or `-1` for all pixels

Defaults:

- `r = 0`
- `g = 0`
- `b = 0`
- `index = -1`

Examples:

```text
led 0 0 32 -1
led 32 0 0 0
```

Success response:

```text
ok,led
```

## Error Responses

The CLI returns simple text errors when parsing or validation fails.

Examples:

```text
error,invalid capture arguments
error,invalid range value
error,invalid dds arguments
error,dma transfer error
```

`SimpleCLI` parser errors are also forwarded as:

```text
error,<SimpleCLI message>
```

## Typical Workflows

### 1. Basic bring-up

```text
id
status
adc
```

### 2. Set source and frontend, then capture one channel

```text
dds 10000 1
amp 160
offset 0
range 1
vpga 2
ipga 2
capture 512 200000 voltage
```

### 3. Capture both synchronous AC channels

```text
capturepair 512 200000
```

### 4. Use with the Python oscilloscope

Run on the PC:

```bash
python3 pc_osc/pc_oscilloscope.py --port /dev/ttyACM0 --baud 115200 --samples 256
```

Then send on the device serial port:

```text
capture 256 200000 voltage
```

## Notes

- The CLI is designed for development and bring-up, not yet for a polished production protocol.
- `capture` is the easiest way to stay compatible with the existing oscilloscope tool.
- `capturepair` is more suitable for future host-side impedance processing.
- The MCP4561 digipot address is fixed in firmware to `47` decimal (`0x2F`).
